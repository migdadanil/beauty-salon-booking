# Техническое задание — Beauty Booking



3.1. Общие сведения. Название: «Beauty Booking». Назначение: веб-приложение для подбора мастера красоты и онлайн-записи. Пользователь видит информацию о мастерах, примеры работ, отзывы, акции с актуальными ценами, выбирает свободное время у любого мастера или записывается к конкретному мастеру на удобное время. Дополнительно: раздел трендов месяца и раздел о брендах косметики (советы профессионалов, исторические факты).

3.2. Цели. Упростить поиск мастера по вкусу и бюджету; убрать двойное бронирование; дать мастерам и администратору инструмент управления расписанием, ценами, акциями и контентом.

3.3. Роли и права.

| Возможность | Гость | Клиент | Мастер | Администратор |
| --- | --- | --- | --- | --- |
| Смотреть мастеров, портфолио, отзывы, акции, тренды, бренды | да | да | да | да |
| Регистрация и вход | да | да | да | да |
| Искать свободное время, записываться, отменять свою запись | нет | да | нет | да (за любого) |
| Оставлять отзыв после завершённой записи | нет | да | нет | нет |
| Менять своё расписание и свои цены | нет | нет | да | да (для любого) |
| Выкладывать работы в портфолио | нет | нет | да (свои) | да (любые) |
| Дописывать факты и советы о брендах | нет | нет | да | да |
| Отмечать запись выполненной | нет | нет | да (свои) | да |
| Управлять услугами, акциями, трендами, брендами, мастерами | нет | нет | акции на свои услуги | да |
| Видеть статистику | нет | нет | по себе | общую |


3.4. Функциональные требования.

- FR-01 Регистрация по email и паролю (пароль не короче 8 символов), роль по умолчанию «клиент».

- FR-02 Вход, выдача JWT-токена, выход.

- FR-03 Каталог мастеров с фильтром по услуге и специализации, сортировкой по рейтингу и цене.

- FR-04 Карточка мастера: описание, опыт, услуги с ценами, портфолио, отзывы, средний рейтинг.

- FR-05 Каталог услуг по категориям; цена с учётом действующих акций (старая цена зачёркнута).

- FR-06 Раздел акций: активные акции со сроками и новой ценой.

- FR-07 Поиск свободного времени у выбранного мастера на выбранную дату с учётом длительности услуги.

- FR-08 Режим «любой мастер»: по услуге и дате показать все свободные слоты всех подходящих мастеров.

- FR-09 Создание записи; система не допускает пересечение записей одного мастера.

- FR-10 Личный кабинет клиента: предстоящие и прошедшие записи, отмена не позднее чем за 2 часа.

- FR-11 Отзыв (оценка 1-5 и текст) только по своей завершённой записи, один отзыв на запись.

- FR-12 Кабинет мастера: записи на день и неделю, отметка «выполнена», редактирование расписания и своих цен.

- FR-13 Портфолио: мастер и админ загружают работы (ссылка на изображение и подпись).

- FR-14 Тренды месяца: админ добавляет и редактирует тренды, пользователи видят тренды текущего месяца.

- FR-15 Бренды: карточки брендов, к каждому советы, факты и история; мастера и админ дописывают материалы.

- FR-16 Админ-панель: пользователи, мастера, услуги, акции, тренды, бренды, статистика (записи, выручка, популярные услуги).

3.5. Нефункциональные требования. Пароли только в виде bcrypt-хеша; доступ к защищённым действиям по JWT; интерфейс адаптивен (телефон и компьютер); ответ API до 1 секунды на тестовых данных; запуск всего проекта командой docker compose up --build; документация API автоматически на /docs.

3.6. Критерии приёмки. Выполнены все FR; сценарий «два клиента на один слот» заканчивается ошибкой для второго; клиент не может открыть админские страницы; все тест-кейсы из docs/tests.md пройдены.
